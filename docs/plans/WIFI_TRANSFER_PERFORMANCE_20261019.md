# Wi-Fi 文件传输提速

2026-10-19用户要求测最大传输速率，并明确“要wifi，越快越好，有什么问题，有什么限制就解决掉”。作为已批准整体验收任务的补充，连续诊断、修改、定向验证；新固件具体试烧门槛仍按发布计划执行。

目标是实际可持续的上传、下载速度。先恢复并验证无线遥测修复，再比较电脑直接HTTP、实际网页和桌面Wi-Fi路径；记录文件大小、原始耗时、有效载荷字节/秒、SHA-256、连接方式、源码/产物和负载。1MiB作为起点，必要时使用更大新建文件区分启动、传输和校验成本。上传与下载分别计时，端到端时间包含最终校验；多轮持续结果不能写成硬件理论极限。

已知源码瓶颈：桌面ManagementClient.FileAction在每次任务查询前固定等待100ms，2048字节分块形成约20KiB/s的理想等待上限，尚非实测Wi-Fi速度。直接HTTP下载file_download.cpp每块等待至少10ms、经文件任务JSON/base64再还原发送，亦存在调度和转换成本。这些静态推算不包含网络、TF读取、摘要和HTTP开销。

受控对照逐项考察轮询等待、HTTP连接复用、内部分块及转换成本。保留旧v2 API兼容、采集互斥、会话/任务身份、无覆盖、取消、最终长度与SHA-256和失败不发布完整文件。协议改动先提供兼容路径和回归，不能通过取消校验获得“提速”。SDK、引脚、分区、PSRAM及采样优先级不顺带调整。若修改桌面程序，按原发布计划升至0.3.1并做真实程序验收。

仅在本轮新建验收目录写入，旧资料不动，凭据与原始日志不公开。保留上一候选及同轮最新配置，出现采集或文件回归即保存现场并处理。最终发布仍须整套矩阵通过。
