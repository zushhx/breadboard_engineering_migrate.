# Windows 主控控制台

2026-10-17，用户要求在桌面建立可独立操作主控的软件，并明确选择“先完成可用桌面版，Wi-Fi／热点通过系统连接向导操作”。本次软件开发、验证、打包和桌面入口已确认，连续完成，不逐文件确认。

## 范围与实现

- 起点 `daabee24e12e18766e12ee3b0d955b9a365f6f6f`，原分支 `codex/realtime-ui-redesign`，工作区干净；新分支 `codex/desktop-controller`。
- Windows 原生 WPF 控制台，使用本机 .NET Framework 4.8 系列编译器和系统 WPF，不引入 NuGet、Python 运行时或安装服务。构建固定实际编译器/框架输入并记录 SHA-256；输出留在忽略的 `local-data/desktop-controller/`。
- 用户随后明确缩小范围：“这些就按照之前的检测页面就行了，设置一个按钮直接打开检测[页]”。采集控制、时长、曲线、INA/TF 和故障显示全部复用原网页；桌面程序只负责地址保存、只读连接检查、受限局域网查找、打开原检测页、网络向导和连接日志。不重复开发采集/图表/导出界面。
- 网络页提供 Windows Wi-Fi/移动热点设置入口和步骤。本机当前固件仅 STA，Wi-Fi 凭据编译注入，无运行时配网/AP 接口；本次不将系统设置入口描述为主控配网或自动创建热点。
- 桌面检查只使用现有 `GET /api/status`，无 POST/录制/串口调用。状态校验 boot/卡身份/阶段。只在用户点击时查询，不轮询；应用单实例，打开检测页后不增加后台设备负载。重复打开提示复用既有浏览器页，用户显式选择再次打开。既有网页的多页面并发问题未修复。
- 不修改固件、SDK、引脚、时钟、初始化、分区、NVS 或 TF 数据格式；不接串口、不复位/烧录、不自动采集/停止或写卡。实机采集验收需可达设备及单独明确测试范围；本轮默认只读连通。
- 发布桌面本机便携版和快捷方式，设置/日志在用户 LocalAppData，不存储 Wi-Fi 密码，不将私人设置/构建产物上传。

## 验收与证据

- 构建原生 EXE，验证程序可启动及中文 UI，检查常用窗口尺寸、缩放、键盘操作、各页和断线提示。预览明确为离线模拟，不执行设备请求或打开系统设置/浏览器。
- 本地模拟 HTTP 设备验证协议/身份、超时、错误页面/重定向、响应边界、地址验证、查找范围及取消；软件只有 GET，不发采集命令。日志不保存 boot 控制令牌。模拟通过不代表真实采集或计量验收。
- 检查最终 diff 和项目路径/冻结基线；使用可用 Code Review 工具，如只返回 CI 诊断则明确不算独立源码审查。按既有路径建立叠加于原任务分支的草稿 PR；不自动合入 main 或原任务分支。
