# IIS3DWB 真实采集与 TF 记录首版方案

日期：2026-10-15；2026-10-16用户在方案备齐后要求“继续”，据此开始本方案范围内的软件开发。具体新候选试烧、实机批次及main合并尚未授权。用户要求暂停精度排查；当前事实见[STATUS](../STATUS.md)，后续验收仍按[WORKFLOW](../WORKFLOW.md)。

## 目标与交付

在当前主控、TF、IIS3DWB和INA226接法上，实现一次显式启动、限定时长、可以正常停止的真实数据记录：三轴原始样本进入TF，INA支路电压/电流/功率以低速附带记录，电脑端可校验并解析出时间轴和波形。首版优先证明数据连续、错误可见、文件可读；不把记录功能等同于计量精度、频响或长期稳定性通过。

交付包括独立固件工程、独立构建入口及输入/产物哈希、受控实机批处理、文件格式说明、主机解析与完整性校验工具、一次合并验收报告。新增工程复制固定输入，不修改已验收候选或冻结文件；从当前任务提交建立 `codex/sensor-tf-recorder` 分支，保留可恢复的7994b9d候选。

## 数据路径与关键选择

1. IIS3DWB按标称26,667组三轴样本/秒、首版±2g采集，读取FIFO的tag与三轴数据，核对tag/状态/溢出。SPI Mode3，现有1 MHz改为目标8 MHz；这是明确的接口配置变化，实物排线能否支持须实测。FIFO具体读法、批量传输边界和清空/停止顺序按ST文档及固定版本驱动核对，不假设寄存器跨帧自动回绕。驱动引用时固定提交及许可证，不从浮动master构建。
2. 采集任务定时服务FIFO，首版不增加INT导线；与独立TF写入任务之间设置有界内存队列。分块写入，避免逐点写文件或逐点串口输出。先按约128 KiB缓冲预算核对内部RAM、最大可用块、DMA要求、任务栈和最坏服务时延，分配不足则拒绝启动，不暗中启用PSRAM。
3. INA目标约10次/秒，单独记录主控单调时间、原始寄存器、换算值及有效性，不占用采集任务等待I2C。单次未就绪标记无效，不输出伪零；身份/配置异常保存现场并终止本轮，不循环补CAL。继续只测传感器支路，精度未验收的标记写进文件元数据。
4. 文件以分块二进制为主：文件头记录固件/构建输入、设备/卡身份、接线版本、量程、标称采样率、SPI配置、INA参数；数据块保存原始FIFO帧、块序号、主控起止时间、样本计数及CRC，尾部保存汇总与正常结束标记。FIFO自带tag计数仅作辅助，不能冒充硬件逐样本全局序号。
5. 电脑工具完整校验文件结构、块连续性、CRC、样本数、尾部状态和错误计数；输出摘要、三轴/INA可选CSV及波形预览。样本时间由标称ODR和块时间锚点估算，注明并非每点精确硬件时间戳，不把主机收包时间当采样时刻。板上完整回读并计算文件摘要，串口只返回摘要和有限预览；本轮结束后由用户在全断电状态把卡移到电脑读卡器，集中导出一次，电脑复算摘要并解析。卡槽操作不带电进行，不引入USB MSC或WiFi来传文件。

按26,667组/秒计算，XYZ六字节净数据为160,002 B/s，FIFO含一字节tag约186,669 B/s；五分钟原始FIFO帧约56 MB，另加块头和INA记录。1 MHz SPI理论仅125,000 B/s，已经不足，不能用当前1 Hz快照冒充连续采集。128 KiB缓冲按FIFO原始帧速率只覆盖约0.70秒，TF偶发长延迟仍可能使其耗尽；须记录高水位、最大写入/同步耗时并据实判定。

115200 baud、8N1串口的理想负载上限为11,520 B/s，传56 MB理论至少约81分钟，实际更长，因此不采用该速率整文件回传。读卡器是本轮主机侧实物文件验证的前提；若当时不可用，板上记录可先验，但电脑解析真实文件保持未完成，另说明替代导出方式及时间成本，不把解析模拟文件当实物验收。

## 固定条件与变更范围

保持PlatformIO6.2.0、espressif32@6.11.0、ESP-IDF5.4.2、CPU160 MHz、PSRAM关闭、8 MiB Flash与原分区。TF保持现有四位SDMMC/请求20 MHz、原引脚/上拉、3V3直供及启动等待5秒；INA保持I2C100 kHz、当前引脚/地址和R100换算参数，SPI引脚不改。引入FIFO、8 MHz SPI、任务/队列、持续TF文件写入与相应初始化/停止顺序，均作为本次显式变更审查。

启动默认空闲且不写卡，不自动开始记录。用户明确启动后才配置本轮采集，身份/关键寄存器读回通过后新建唯一目录/文件；避免覆盖已有数据。停止时先停止传感器入FIFO、排空残余数据和队列，再同步/关闭文件，记录每步结果。对意外复位留下的无结束标记文件，只读扫描完整CRC块并标记未完成；不自动修复/截断/删除或宣称已经具备断电保护。

首版不加入WiFi、在线图表、FFT/故障识别、USB盘符、自动上电录制、校准补偿或整机电流测量。±2g可能在实际振动中饱和，首轮记录饱和计数；本轮不以强敲或实际加工负载验收，后续根据负载决定量程。

## 软件与实机验收

软件阶段一次完成实现、自行差异审查、项目检查、固定环境构建及必要的解析/边界测试。测试聚焦损坏/截断文件检测、块计数、缓冲满处理、启动/停止状态和错误传播；不为已有未修改路径重复造测试。记录是否取得独立审查，CI/编译不替代实机结果。

候选产物、哈希、备份范围和回退步骤备齐、CI通过后，再申请一次具体候选的整轮试烧授权。拟合并执行：

- 一次候选试烧后的身份/配置/TF参考文件核对，随后连续记录约5分钟，正常停止并完整读取校验本轮文件。检查FIFO溢出、软件丢弃/队列满、tag/传输/写入错误均为0，块/帧数与尾部汇总一致；记录实际平均速率、FIFO/队列高水位、写入时延和最小剩余堆/栈。样本数与计时应符合标称ODR及其文档误差；没有独立时基，不声称完成采样时钟计量验收。
- 保持模块和卡供电的MCU复位后检查挂载、旧文件与一次简短新记录；两次由用户确认全断电后的检查各只做初始化、参考/已有文件复核与约10秒新记录。将新固件必要启动回归并入这一轮，不重复旧版10×1 MiB、旧五分钟文件压力循环或INA精度测量。
- 新文件完整结构/CRC与摘要均通过，正常结束标记有效；旧参考文件摘要保持匹配。只报告本次条件下未观察到丢失，计数机制不提供物理上零丢样的绝对证明。主测试异常立即留日志和完整/未完成文件，停止扩展测试；恢复已保留模块候选后做针对性只读复核。

两次真断电属于新TF数据路径按现行流程需要的回归，不能用MCU复位替代。写入中强制复位/断电不包含在本轮，暂不增加此项交互。实机总时长包含烧录、约5分钟主记录、文件传输和人工断电等待，不承诺五分钟内全部完成。

## 风险、验收边界与恢复

主要不确定项为面包板排线在8 MHz下的信号质量、无中断轮询的FIFO服务时延、内部RAM预算和TF写入长尾。若任一项无法满足，先保存证据再提出具体调整，不同时更换SDK、PSRAM、接线和时钟来掩盖原因，不以自动降采样但仍标满速的方式通过。软件队列满或FIFO溢出必须记录并使该轮失败。

回退使用已封存7994b9d固件及其构建清单、接线表和实机日志；新试烧前保存受影响Flash范围并复核哈希。新的8 MHz设置不写持久化分区，恢复旧程序后模块仍需按旧流程重新初始化。新固件试烧和稳定分支合并分别确认；本方案本身不构成新候选试烧授权。

依据：[ST IIS3DWB DS12569 Rev8](https://www.st.com/resource/en/datasheet/iis3dwb.pdf)，尤其SPI上限10 MHz、标称26.667 kHz和FIFO七字节帧说明；[ST官方驱动接口](https://github.com/STMicroelectronics/iis3dwb-pid)。8 MHz为本方案选择，非已通过的板级能力。
