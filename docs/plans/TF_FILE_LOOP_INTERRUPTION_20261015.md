## 合并操作与验收

1. 同一主控 `44:1b:f6:81:91:10`、同一卡 `10044BA5` / 7,948,206,080 字节；核对本地固件输入、产物、干净任务提交和批准记录后连接串口。
2. 文件写读循环约 300 秒，最多 60 个新文件，每个 1 MiB；每个完成写入、同步、关闭、完整重读和固定 SHA-256 检查。先到的时间/文件数限制停止；最后一个文件跨过 300 秒时待其完成。逐个保存检查点，记录实际数量、字节和时长，不能把上限当作实际完成量。
3. 再创建一个测试文件。看到 `create_new fatfs=0` 后等待 200 ms，且未看到同步、关闭或终态，执行一次 RTS/EN 主控复位。触发点不是仪器观测的瞬间电气写活动；卡供电保留，不称为写入中真实断电。
4. 验证同一诊断固件重新启动、卡初始化及挂载成功；再写一个完整 1 MiB 新文件，复核上一轮一个已完成旧文件和本轮最后完成的文件，检查根目录与原参考文件。
5. 中断文件保留，不检查/恢复其内容，不计为完整通过。意外失败保存现场后停止，不自动重试、重刷、格式化或修复。

## 范围、成本与回退

本轮只修改主机批处理与报告，现有固件、SDK、TF 引脚/时钟/PSRAM/初始化/分区不变，不重做已通过的两次断电和全部 40 次基础校验。新增批准范围仅对应本轮有上限的写卡和主动 MCU 复位，不含 main 合并或发布。

主控继续运行现有诊断固件。异常时脚本退出，卡上文件及日志保留；正常基线及上轮主控快照仍在。未新增自动恢复烧录；重刷、文件系统修复或修改供电时另明确方案，不能把恢复固件当作恢复卡内文件。

这是“写入—关闭—回读”文件操作循环，有读回停顿，不是实时采集压力验证。旧配置目标为 26,667 样本/秒 × 6 字节，即 160,002 字节/秒；本轮不据循环平均速度断言该负载无丢失。真正持续采集、缓冲积压、写入中真实断电、空间泄漏/全卡完整性和长期稳定性仍未验收。

工具入口 `tools/tf_write_endurance.py`，与构建分离。新增无批准/范围不符时设备发现前停止，以及同步或完成后不得再主动复位的边界测试；故障模拟不接触实机。最终报告注明作者自行复核，不冒充独立审查。
