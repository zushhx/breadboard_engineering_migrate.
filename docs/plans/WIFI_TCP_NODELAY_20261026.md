## 改动与影响

1. 将 R240 诊断入口、镜像 hook 和必要主机接收工具移植到最新基线，保留三档量程、热点保存确认及 USB 行为。默认无测速服务，须显式 ARM；合成 TF 写入另走受控命令。
2. 保留已有端口复用、监听就绪、整轮节拍、后台落盘修复。发送端 accepted socket 启用并回读 `TCP_NODELAY=1`；设置或回读异常立即拒绝该会话。记录会话开始/结束的有限堆状态，避免传输中周期串口输出。
3. 固定 SDK、CPU、PSRAM、引脚、SDMMC/SPI、分区、250 ms 发送期限、25600 字节 FIFO、帧格式、240000 B/s 及任务优先级。新增诊断会增加运行内存和发送负载，其实机余量另测。
4. 主机工具恢复版本更新为上述 421da25；准备、烧录、测试分阶段，批准绑定当前输入和新产物。失败后先结束活动 TF 源再恢复同轮已核验镜像/NVS，保留失败文件与日志。

## 验证和恢复

- 软件：生产路径宿主测试覆盖 NODELAY 设置/回读失败与关闭、监听、节拍、发送取证、FIFO和接收完整性；针对性量程/热点/录制回归，固定工具链干净构建，最终 diff 另一 agent 审查。
- 核对新旧生成 SDK、分区和凭据头一致；旧基线镜像按记录哈希校验，在 ignored 本地目录保留，正常产物不覆盖。
- 新实机批准后先纯 RAM 30 秒，配合主机 TCP 抓包区分 ACK、重传、零窗口；通过后执行原合成/真实 30、200 秒及三档回归。抓包权限和设备独占在实际运行前核实，准备阶段不启动抓包/串口/网络配置。
- 完整字节、零丢弃、整轮速率与延迟分开报告。此前 100 ms 端到端目标仍需样本时间戳及钟差上界；单独吞吐通过不记为端到端通过。
- 新试烧前核实实际主控身份、运行来源、卡片及空闲状态，保存当轮 Flash/NVS；失败按已批准恢复范围处理。两次真断电需用户实际操作。当前只准备软件，不合并 main、不发布。
- 本机已发现 Windows PktMon；只读 `pktmon status` 返回拒绝访问，当前会话缺抓包权限。实际抓包需管理员入口并先检查现有会话/过滤器，限定主控 IP 与 TCP 19000，保留原始 ETL 和 PCAPNG。未执行启动、停止、过滤器修改或抓包。
