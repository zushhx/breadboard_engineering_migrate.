## 失败现场

固件启动TF只读识别和参考文件读取通过，模块只读身份有效；首次显式初始化前INA CONFIG4127/CAL0000及无效测量为预期默认状态。126720字节INTERNAL|8BIT池申请成功，记录before_free=282896、after_free=155916；before/after_largest均31744，原诊断疑点仍未解释，不据此认定内存足够或内存损坏。

日志显示WiFi配置NVS禁用、STA模式启动，随后出现：

```text
assert failed: vTaskGenericNotifyGiveFromISR ... tasks.c:6204
xEventListItem.pxContainer must be NULL
```

现场记录3次相同断言及自动重启，属于**一次试烧后的自动启动循环**，不是3次改变变量的受控实验。日志没有WiFi取得IP/HTTP启动成功，没有发出REC_START，浏览器阶段未启动，也没有观察到新REC文件。宿主程序最终因未取得稳定的候选身份应答而停止，该错误是启动崩溃的后续门槛失败，不能解释成已经证实烧错主控或镜像。

使用对应ELF及固定xtensa-esp32s3-elf-addr2line离线解析，直接断言路径为timer_alarm_handler → vTaskNotifyGiveFromISR → tasks.c:6204。被中断的任务栈包含ppTask → ieee80211_ioctl_process → pm_wake_done → pm_disconnected_sleep → esp_phy_disable_wrapper → esp_phy_disable → phy_track_pll_deinit → esp_timer_delete。完整原始回溯、符号结果、备份及日志哈希在[证据清单](SENSOR_WEB_FIRST_TRIAL_EVIDENCE_20261016.json)。

## 已证实、未证实与替代解释

- 已证实：本候选启用WiFi后触发FreeRTOS断言，未进入录制；该条件下不能交付网页功能。断言与被中断栈给出系统定时器通知及WiFi断连省电/PHY定时器删除的排查线索。
- 未证实：通知任务状态异常的技术根因。中断栈不等于被中断函数已经造成错误，不能仅凭pm_disconnected_sleep判定省电配置是唯一原因，也不能据此声称SDK缺陷、堆耗尽或供电问题已定位。
- 仍需区分：RTOS任务/通知状态、定时器删除时序、内存破坏或栈边界，以及供电瞬态。日志未见brownout不能排除供电；没有独立电源波形。池申请成功不能证明运行内存及栈完整。
- 本轮未改SDK、CPU、PSRAM、TF/SPI时钟、分区、传感器或INA参数。没有用关闭断言、扩大栈、切换SDK或重新接线来尝试“刷到成功”。此前旧largest字段异常仍单独保留，未证明与本次崩溃同根。
