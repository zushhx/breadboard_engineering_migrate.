# 目标与下一版计划

批准日期：2026-10-15。任务进展与当前能力在 [STATUS.md](STATUS.md) 维护；本页维护目标与验收要求。

## v0.1.0：工程基线版

目标：文件有清楚位置，当前状态有唯一入口，正常版本能追溯，工程修改经过审查及相应验收。

| 工作 | 交付与验收 |
|---|---|
| 现状与正常版本封存 | 初始 Git 提交、基线标签、正常产物、完整构建输入、哈希、接线与证据清单 |
| 文件整理 | 目录分区、逐文件迁移映射、原始内容核对；生成物与私人备份不入普通代码提交 |
| 上下文治理 | 全局规则、项目约定、导航、状态、计划、流程各有职责；旧 README 与记忆归档 |
| 故障复盘 | 时间线、证实与未证实结论、流程责任、预防措施、后续验证问题 |
| 构建与操作入口 | 指定环境、冻结输入、独立输出；普通构建不触发上传，硬件操作带版本和批准记录 |
| Git 与检查 | 任务分支、小步提交、PR 模板、本地检查及 CI 配置；记录实际执行的检查 |
| 本机全局规范 | 原规则备份、独立 Git 修订记录、部署校验、当前会话载入证据 |

本版完成不代表原业务迁移、TF 写入或长期稳定性通过。`v0.1.0` 稳定标签在审查验收并由用户确认合并之后建立。

## 后续任务顺序

1. **TF 写入与恢复能力**：先批准写卡计划及数据备份；按新 SDK 验证新建文件、写入、同步、关闭、重新打开完整校验及异常中断处理。明确原数据保护和测试文件清理范围。
2. **模块接入，再集成真实采集与存储**：按[模块接入计划](plans/SENSOR_MONITOR_BRINGUP_20261015.md)确认身份、配置、基本数据及电流监测范围。[INA226 电压、电流核验](plans/INA226_PRECISION_CHECK_20261015.md)按用户最新决定暂缓，仍保留未验收边界；下一步按[真实采集与TF记录方案](plans/SENSOR_TF_RECORDER_20261015.md)规划FIFO、缓冲写卡、参考监测和主机解析，验证采样率、完整性、分段连续性及异常计数。不把历史模块检查或功能连通当作精度验收。
3. **实时界面与整机运行**：按[手机热点界面方案](plans/SENSOR_WEB_CONTROL_20261016.md)先开发实时状态、短窗口预览与录制控制，再结合实际采集和写卡负载验证 UI、并发、功耗、温升与持续运行；供电修改单独立项和验收。
4. **电脑桌面自主操作入口**（用户于2026-10-17追加确认）：按[桌面控制台方案](plans/DESKTOP_CONTROLLER_20261017.md)提供可双击运行的 Windows 程序、主控查找与地址保存、网络连接指引和直接打开现有检测页面的按钮；采集控制和图表沿用原网页。用户随后批准[USB、主控Wi-Fi/AP、会话和网页TF方案](plans/CONTROLLER_V2_20261017.md)；桌面不设TF页。实际范围和未验收项只在STATUS维护。

每项后续工作先给具体方案，再开发、审查、申请试烧及实机验收。历史文档中的 v1/v2 硬件命名保留为历史，不与上述工程版本混用。
