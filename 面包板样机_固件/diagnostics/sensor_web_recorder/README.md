## 时间命名候选

2026-10-18按[已确认方案](../../../docs/plans/RECORD_TIME_NAMES_20261018.md)准备新候选：网页提交控制端本地时间`YY-MM-DD-HH.mm.ss`，主控用单调计时补偿准备/接管等待，记录保存为`/26-10-18-15.46/26-10-18-15.46.BIN`，同一分钟从`-02`顺序选空目录，不覆盖历史项目。两位年限定2000–2099，闰日等日期校验；不依赖NTP或设备RTC。状态`record_name/record_path`提供实际名称，网页和桌面下载沿用实际文件名。旧客户端缺少local_time仍使用旧REC_/DATA.BIN，不猜测年月日；升级后应刷新检测页。

文件格式、采样配置、run会话身份、模块启动顺序不变。新目录查询仍在准备阶段，若模块准备跨分钟，在首次写卡前重新选择该分钟的空目录；查询失败不继续写入。历史`REC_VERIFY <run>`保持；新时间名可用只读`REC_VERIFY_NAME 26-10-18-15.46[-02]`验证（括号只表示可选序号，实际命令不含括号）。候选构建不代表已经刷入或通过实机验收。

## 构建

使用项目PowerShell7.6.6执行`.shell-tools/build_sensor_web_recorder_pwsh7.ps1`。默认空凭据，网络禁用，供CI构建；加入`-WifiConfig local-data/config/sensor-web-wifi.json`才注入本地凭据。JSON具有ssid/password两个字符串，须放忽略的local-data；不将实际值写入源码、报告或CI。`-PrepareOnly`仅生成独立暂存输入。凭据头只在私人ASCII构建目录，含凭据产物/完整清单保留local-data，不能公开发布。构建入口不访问串口、不复位、不烧录或读写卡。

SDK版本/CPU/PSRAM/分区/引脚/TF/传感器参数保持前版；构建逐项核对SDK有效配置和冻结分区，仅允许CONFIG_ESP_PHY_CALIBRATION_AND_DATA_STORAGE由y变n，防止PHY自动持久化射频校准。WiFi自身另设nvs_enable=0及RAM存储，不初始化NVS；每次上电做射频校准，耗时/供电待实测。新增依赖为固定SDK内置WiFi、esp_netif、event、HTTP server、cJSON。网页作为由构建入口生成的只读C++资产，源HTML纳入构建哈希。平台上传guard保留；正常记录器和冻结基线保持不变。

## 连接与控制

固定SDK的esp_phy/sdkconfig.rename把CONFIG_ESP32_PHY_CALIBRATION_AND_DATA_STORAGE旧名映射至上述新名。新候选两键均关闭，构建要求两键同时从y变为未设置；其他SDK差异拒绝。它们属于同一个RF持久化选项。

设备仅以STA加入2.4GHz手机热点，不提供AP、不桥接互联网、不写WiFi凭据到NVS。电脑连接同热点并通过手机移动数据上网；主控串口输出`[web] address=http://.../`，浏览器打开该地址。热点客户端互访能力和电脑外网并存须实测。无凭据或网络初始化失败仍保留串口；网络断连仅尝试重连，不改变已启动记录。

上电保持五秒等待及原只读检查，预留原40块126720字节采集池，再启动网络。网页每200ms串行查询`GET /api/status`，无重叠请求。短窗口最多5Hz，每窗口至多272个连续XYZ样本（约10.16ms），未覆盖窗口间数据；完整FIFO仍写TF。不作为FFT/计量/独立零丢样证明。INA只来自已存在的监测队列，不另读I2C；无效或未采样显示空值，停止后明确为最后快照。

新版额外每秒串行查询`GET /api/trend`，不会与status重叠。返回boot/run、sample_rate=26667、window_samples=5333及最多150个`[结束样本序号,X_RMS_ug,Y_RMS_ug,Z_RMS_ug,近满量程轴值数]`。统计在记录所有者收到的每个完整块上、原始预览节流之前累积全部样本；每完整窗口逐轴去均值再计算RMS，停止后的不满窗口不发布。时间按标称采样率估算，非独立时基或计量校准。历史使用固定环形数组，HTTP副本及输出缓冲为静态，不在网络任务访问TF、传感器或动态扩展历史。

主图显示最近约30秒RMS，三轴固定0..2000mg；原始图三轴固定-2000..2000mg，不自动缩放。1/5/10ms均逐点显示同一连续原始片段内的采样点，最大272点约10.16ms，不拼接不同片段；末包不足所选视窗时只显示实际覆盖部分。原始中转数组和8192字节状态JSON缓冲保持静态，HTTP栈中的Snapshot小于3KiB。旧1s/10s保峰历史及/api/wave已移除，回收512桶及副本的静态RAM。悬停/触摸/方向键查看实际采样点，点击固定、Esc清除。

剩余容量通过/api/status的space_valid及free_bytes十进制字节字符串发布，卡总容量仍是物理容量。唯一存储主任务在已挂载的启动阶段和记录命令结束后调用FatFS f_getfree，空闲簇×每簇扇区数×512，使用64位并检查物理容量边界。录制前复用既有空间检查；采集中每秒只发布FatFS已有有效空闲簇缓存，不额外扫描FAT。HTTP/采集任务不读取TF。查询失败或缓存未知显示不可用；0字节是有效值，断线标注旧快照。没有新增格式化、修复或写卡入口。

暂停只冻结画面，不停止采集、状态查询或后台历史更新；新run/boot清空旧图和光标。趋势接口失效保留并标注最后数据，不阻止原状态及停止控制；设备重启后旧页面需刷新会话。所有图只在显式录制后产生数据，停止/待机保留最后快照。30/60/90秒快捷按钮只设置时长，不提交录制。新增连续计算、静态RAM及HTTP流量的实机影响须按具体候选验证。

`POST /api/start`需启动级随机X-Record-Key头及JSON的run/seconds/card_serial/card_bytes。校验卡身份、容量、1..300秒、run格式；单槽请求，忙/锁定拒绝。主循环取出后依次检查空间/目录/内存/模块，仍唯一访问FatFS。`POST /api/stop`为零body，仅请求停止，重复停止不写新文件。queued可取消；准备/采集期间停止交由记录路径安全排空，关闭/校验期间不打断。所有阶段完成且写读摘要一致才显示通过。开机令牌变更后旧页面只能查询，必须刷新取得新会话才可控制。

无CORS，同源自定义头防跨站普通请求；同热点获准客户端可打开页面并控制，未提供独立账户认证。热点密码不嵌入网页。刷新/自动重连只查询、不重发命令；POST超时显示结果未确认，用户先查看设备状态。运行编号使用浏览器随机数，目录仍用CREATE_NEW且拒绝覆盖。

原串口协议和I3REC001保持兼容，格式细节见[前版说明](../sensor_tf_recorder/README.md)。录制中只有REC_STOP，页面不开放旧WRITE_TEST、格式化、删除、修复或下载。主任务仍写文件，采集任务只SPI，INA任务只监测；预览发布在主任务已取出的块上，网络只读副本。短临界区不含网络、文件、分配或硬件调用。

## 验收与恢复

原记录器已通过的有限实机结果不扩展到本候选。网络带来内存、调度及供电变化，后续按方案请求具体试烧；网络互访、五分钟并发负载、复位/两次真断电及导出校验未测。pool同能力前后统计用于核对旧largest疑点，未擅自归因或更换SDK。扩大时长/缓冲、写入中断电及手机睡眠兼容性不由软件构建代替。

恢复目标为已保留203a60b记录候选，其产物哈希/接法见STATUS。本阶段未连接硬件，未执行新恢复路径。
