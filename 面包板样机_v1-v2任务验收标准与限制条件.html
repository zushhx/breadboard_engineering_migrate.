零、先对齐：这里的「第一版 / 第二版」指什么

叫法指什么状态与口径来源
第一版 v1 当前这块面包板样机（830 + 2×400）上的这版任务 电子链路验证 + 实时显示为主线。口径来源：2026-09-18 20:32 你的原话「这一版先显示实时数据吧」
第二版 v2 下一板的任务（改供电为主） 「实时 + 写卡」要能同时跑、不再受板载 LDO 热限制。口径来源：同上「等到下一板我给他无线充电加大功率，给他实时还有写 sd 卡都可以」
⚠ 有一处口径需要现在就说清：你原话里的「下一板加大无线充功率」解决不了供电余量问题。
板载 LDO 的发热只取决于自身压差 × 输出电流，跟输入端能送多少功率无关 —— 现在 Qi 5W 相对系统需要的 0.95 W 已有 4 倍以上余量，从来不是瓶颈。
更糟的是：Qi EPP 15W 的接收端输出是 9V / 12V 不是 5V，沿用 LDO 做 9V→3.3V 就是 (9−3.3)×0.21 ≈ 1.2 W，SOT-23-5 必热关断。
→ 所以 v2 的主线是「换 buck / 电池直出」，不是「加大无线充功率」。详见 §2。

一、第一版任务（v1）

1.1 任务定义

一句话：在面包板上把「振动采集 → 处理 → 实时显示 +（可选）落盘」这条电子链路走通，并产出一份 PC 上可解析的原始数据。

B 组 · 实时显示（v1 的主线，必须过）

#判据量化口径
B1手机 / 电脑连上设备热点 → 浏览器打开 UI，波形持续刷新抽帧 26667 ÷ 26 = 1026 Hz，32 点/帧 → ≈32 fps，398 B/帧，上行 12.7 KB/s
B2静置时 Z 轴显示 ≈ 0 g（不是 1 g）去直流生效：3 s 一阶低通估 DC，对应截止 ≈0.05 Hz
B3敲桌面时波形出现明显冲击判据用「冲击峰高与原始数据算出的峰值偏差 <10%」
B4抽帧不丢峰值必须用 min/max 包络，不能隔点抽样 —— 崩刃/冲击是窄脉冲，隔点会整段抽没。RMS 在全速原始样本上求均方，不是抽帧后求
B5状态栏 2 Hz 更新：电量、Qi 状态、电流、SD 剩余JSON 文本广播，约 1 KB/s
B6改界面不必重编译页面优先从 TF 卡 /ui.html 加载，卡上没有才用固件内嵌版

C 组 · 数据质量（写卡链路）两个数必须都是 0

#判据口径
C1UI「① 缓冲溢出丢样本」= 0采集端太快，192 KB PSRAM 环形缓冲被写满
C2UI「② 写卡失败丢样本」= 0，且写失败次数 = 0存储端出问题（卡满 / 掉卡 / 坏块）
C3段文件头 RecTail 四个数齐全dropSamples / writtenSamples / writeFails / lostByWrite（偏移 16，共 16 B）
C4分段落盘生效每 10 s 换一个文件（MAX_SEGMENT_SEC），掉电最多丢当前段 ≈1.6 MB
C5重启不覆盖旧数据上电扫描卡上最大 vib_%05d.bin 编号后 +1 继续写
B/C 组的关系（关键）：C1 与 C2 是两种不同的故障（采集端 vs 存储端），只有两个都是 0，这段数据才算完整 —— 只看一个会误判。

D 组 · 供电与热

#判据口径
D13V3 轨并 ≥470 µF 低 ESR 电解 + 100 nF治瞬态跌落（TX 突发 355 mA 造成的几十 mV 塌陷 → 传感器复位 / TF 掉卡）。零成本零风险，没理由不做
D2采集 + 推流连跑 10 分钟，LDO 附近手背可停留 5 秒（约 <60 °C）耗散约 320 mW（只推流）；烫手就先关 WiFi 并安排改 buck
D3热预算记录留档，用于 v2 对比推流+写卡 ≈230 mA / 约 390 mW（写卡增量只有 +40 mA / +70 mW，即 +22%）

1.3 限制条件（v1 不许越的线）

#约束为什么
1原嘉立创工程 只读，永不改动它是原装置的判据来源，一改就失去对照基准
2面包板阶段只插不焊；不拆焊板载 LDO、不做改板动作例外只有两处离线准备：焊排针、磁珠分轨（INA226 沿用模块自带分流，不拆焊）
3采样率先 3.3 / 6.6 kHz 打通，再往 26.667 kHz 提一上来追满速会把"链路不通"和"吞吐不够"两个问题混在一起查
4大电流路径必须飞线，不走面包板触点触点 10~50 mΩ/点，直接污染 INA226 读数
5INA226 的 IN+/IN− 必须开尔文接在分流电阻两端（模块 PCB 上本就直连电阻焊盘，天然成立）；分流电阻保持模块自带的 0.1 Ω，不拆焊（2026-09-21 决定）不换的代价只有一个：满量程 ±0.8192 A。当前峰值 456 mA 有 1.8 倍余量；实测一旦超过约 800 mA（典型场景：Qi 同时供设备 + 给电池充电）即饱和，届时再换 10 mΩ（备用件已在手，软件只改 config.h 两个宏，CAL 恒为 2048）
6每接一个新模块先测通断再上电；每次只动一处这是唯一能在烧件前拦住错误的动作
73V3_SENS 必须经磁珠分轨，黄轨白轨之间不得直连直连会让开关噪声直接调制进加速度信号，事后无法从数据里剥离
8WiFi 与采集共存必须实测；若 LDO 烫手 → 用「排障 · 录制时关 WiFi」切工况录数据不许用"砍掉写卡功能"来省电。写卡只多 70 mW，且 M4 存储是 MVP 四项之一
9SPI / SDMMC 线束 <15 cm面包板已是信号完整性的硬约束
10电解电容长脚 = 正、LED 长脚 = 正；100 nF 必须是 X7R电解接反会炸；Y5V 介质容值随温度/电压暴跌，做不了去耦
11DIL24 脚位按实物丝印，不按芯片脚号接错电源可能烧掉评估板，补货要走海外
12软件不引入第三方库（HTTP/WebSocket/SHA-1/base64 全部自写）；交付物 xlsx 一律静态值零公式少一个构建期依赖就少一处下载失败风险；本机无重算引擎，公式会显示空白
13通讯架构的适用性边界：SoftAP + 浏览器只是台式验证形态刀柄是装夹件、可能是旋转件，人不会守在旁边连热点 → 不许把它当成刀柄上的最终方案

1.4 v1 明确不验收的（避免误判为失败）

  • 不要求无线充给电池充上电（P8 推后，本轮未采购电池）
  • 不要求 26.667 kHz 满速下丢帧为 0 —— 先看吞吐余量与实测丢帧率
  • 不要求电量读数准确：分压网络未在实物校准，且电量用开路电压法估算（无库仑计），平台区误差可达 ±15%
  • 不要求射频性能、机械集成、旋转动平衡、小型化（Won't 清单）
  • 不要求 ADC 双路（电量 / Qi）读数精度优于 ±5%（analogReadMilliVolts() 走 eFuse Vref 校准）

二、第二版任务（v2）

2.1 任务定义

一句话：把 v1 暴露出来的供电瓶颈解决掉，让「实时 + 写卡」在正常工况下能长时间同时稳定运行，并把电池链路接成闭环。

任务内容要点
T1供电改造：去掉板载 LDO 的热瓶颈两条候选：① 外置同步 buck（TPS62130 / MP2315 类）5V→3.3V，效率 66%→90%，发热 357 mW → 约 40 mW；② 电池直出 + buck-boost（原设计 TPS63031 就是干这个），一次解决「电池 <3.3 V 失压」与发热
T2电源轨再平衡（v1 现在就能做，v2 固化）方案 ④（推荐）：buck 降到 3.80 V 喂开发板 5V 脚 → 板载 LDO 照常工作但压差只剩 0.5 V，耗散 (3.8−3.3)×0.23 ≈ 115 mW（原 390 mW，降到 1/3.4）。只需改一根杜邦线，不用管反灌。⚠ 此期间不能插 USB
T3电池链路闭环（P8）Qi 接收模块自带充电管理（4.2 V ≤0.6 A）→ 电池 → 系统。TP4056 可省，比原设计少一级
T4通讯架构重新选型（若上真刀柄）BLE / 离线取卡 / 其他 —— 不能沿用 SoftAP 假设

2.2 验收标准

组判据口径
A 热满载（WiFi TX + TF 写 + 采集）连跑 30 分钟，3.3 V 稳压器件表面温度 <60 °C；LDO 耗散降至 <150 mW走方案 ④ 时约 115 mW；走 ① 时接近 0 mW
B 并行「实时 + 写卡」连跑 30 分钟，UI 上 ① 与 ② 都保持 0这才是"能不能同时跑"的唯一判据（v1 里这一项未实测）
C 电池拔 USB 后系统持续工作；充电指示正常；CHRG_N / CHRG_DONE 与 IO7 / IO8 读值一致；BAT_N 与 GND 保持隔离电池负是独立节点（经 8205A 到 P−）
D 无线充确认接收模块两路输出（5 V / 4.2 V）是否同时可用；若提到 EPP 15W → 必须配套 buckEPP 输出是 9V/12V，沿用 LDO 做 9V→3.3V = 1.2 W，SOT-23-5 必热关断（ME6217 热关断点 160 °C）
E 回归v1 已通过的全部判据（P1~P7 + B/C 组）在 v2 上不劣化见 §三 基线表

2.3 限制条件

#约束为什么
1保真侧一律不动：IIS3DWB 型号、INA226 模块（含自带 0.1 Ω 分流）、3V3_SENS 磁珠分轨这些是"被读的物理量"所在的地方，改了测量基准就变了
2不能沿用 LDO 承受 >5 V 输入EPP 9V/12V 直接否 —— 发热 = 压差 × 电流，与输入功率无关
3「加大无线充功率」不是供电余量的解法Qi 5W 相对需要的 0.95 W 已有 4 倍余量，输入端从来不是瓶颈
4不是「做了 buck 就不用大电容」：③ 电容与 ①/④ buck 都要做③ 治瞬态跌落（µs~ms 毛刺，buck 环路带宽跟不上 355 mA 的跳变）；①/④ 治稳态温升（分钟级平均耗散，电容只能摊平不能减少产热）
5面包板能跑 ≠ PCB 能跑面包板寄生电容"帮"了高速信号，升频与改板都要重新验证
6旋转件上的无线传输不在 v2 范围替代滑环、动平衡、传输可靠性是另一个量级的题目，与"面包板验证电子链路"不是一回事
7不得改动 v1 的判据基线（P0~P9 判据文本与红线）基线一动，前后两版就无法比较

2.4 需要你拍板的 3 件事

待定项选项
v2 硬件形态① 改板（自绘 PCB，彻底）／ ② 外置 buck 模块旁路（一个模块 + 一根杜邦线，本周末就能做）
v2 无线充功率① 维持 5W（够用，4 倍余量，零改动）／ ② 上 EPP（必须配套 buck）
通讯架构① 继续 SoftAP（只适合台面）／ ② 先按"离线取卡"做（更接近真刀柄）
